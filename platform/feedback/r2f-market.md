## Round 2, after the adversarial review

What the review left open, and what changed. Every finding was checked in the running build first.

- [4] Reaching the row however the address is opened: fixed. The jump used to run only on a followed link (PUSH), so opening `/app/marketplace?project={id}#new-for-projects` in a new tab, pasting it or reloading it stayed at the top (measured: row at 889 of 900 px at 1440, 1043 of 844 at 390, scroll 0). Scrolling on navigation is now one pure rule, `scrollPlan` in `src/app/scrollMemory.ts`, applied by the shell: Back and Forward restore the remembered position; any other arrival with a hash goes to its target, a fresh load included. Discover only skips its own scroll while the shell is restoring a position.
- [4] Back from a folder returns to the row: fixed. Positions were read after the next page had rendered, so a shorter page had already clamped them (or a lower one kept the old offset). They are now recorded as the person scrolls, per history entry, and a restore retries for a few frames while a long page fills in. Measured: home link (row at 634 px), open Structure, Back, scroller back at 634 at 1440 and 1024, and at 971 at 390.
- Sidebar Marketplace from a scrolled Marketplace: fixed. A navigation that adds a history entry to the same page with a different address (the sidebar's Marketplace from `?project=`, opening a category folder) now starts at the top. One that only replaces the address (typing a search, a filter) keeps the position, as before.
- [C4] Material page links back to the Marketplace: fixed. The top bar's Marketplace crumb and "Browse the Marketplace" carry the visit's project (`?project=`) when the address names one the viewer works on, through the pure `addressProjectFor` (also used by `checkingProjectFor`). The visit keeps its check until the person leaves the Marketplace. Nothing is stored.
- [C4] A sandbox that already stored a project from a link under the old behaviour: not changed here. It needs a one-off migration of stored state, which belongs to the upgrade package (src/store/app.ts persist merge). For the upgrade package owner: on load, clear `ui.checkingProjectId` once (a marker in `ui` that the store sets on any explicit choice tells old records from new), without re-seeding. Until then the person clears it with the X in the checking strip.
- [6] Waiting client: fixed. The setup checklist's waiting steps (Client, and Send while the client has not accepted) and the client-link banner use the same neutral MailQuestion envelope as the header pill, not the blue hourglass. Note for the merge: `ClientLinkBanner.tsx` line 7 (the lucide import) is also changed on the client_consultant branch; keep both sides' icons.
- [14] Quarter helpers: deletion would delete their tests (P8: `format.test.ts` B14.16 and `dates.test.ts` formatQuarter), so they stay, and a new guard in `src/domain/reference/no-quarter.test.ts` fails if any source file other than the four allowed ones (dates.ts and format.ts, which define them; programme.ts, the programme package's axis; publicListing.ts, whose label is never rendered) calls `formatQuarter` or `format.quarter`, or if any screen reads a public `availability.label`. The programme axis quarter labels themselves are the programme package's part of the note.
- Steel columns drawn lying down: fixed. `SectionAxo` draws a UC as a column standing upright in isometric (the section at its top end, hatched; the length dimensioned up its right edge), on cards, thumbnails and the stage, matching the 3D view and the IFC. The 3D view's length toggle shows a vertical arrows icon for a column (new `upright` on `ModelGeometry`, from the same `isColumn` test the mesh uses). Beams are unchanged.
